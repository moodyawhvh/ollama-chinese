## 如何升级 Ollama?

macOS 和 Windows 上的 Ollama 会自动下载更新。点击任务栏或菜单栏中的 Ollama 图标,然后点击"Restart to update"(重启以更新)即可应用更新。你也可以[手动](https://ollama.com/download/)下载最新版本来安装更新。

在 Linux 上,重新运行安装脚本即可:

```shell
curl -fsSL https://ollama.com/install.sh | sh
```

## 如何指定上下文窗口大小?

默认情况下,Ollama 使用 4096 token 的上下文窗口大小。

可以通过 `OLLAMA_CONTEXT_LENGTH` 环境变量覆盖默认值。例如,把默认上下文窗口设为 8K:

```shell
OLLAMA_CONTEXT_LENGTH=8192 ollama serve
```

使用 `ollama run` 时,可用 `/set parameter` 修改:

```shell
/set parameter num_ctx 4096
```

通过 API 调用时,指定 `num_ctx` 参数:

```shell
curl http://localhost:11434/api/generate -d '{
  "model": "llama3.2",
  "prompt": "Why is the sky blue?",
  "options": {
    "num_ctx": 4096
  }
}'
```

## 如何判断模型是否加载到了 GPU 上?

使用 `ollama ps` 命令查看当前加载进内存的模型。

```shell
ollama ps
```

<Info>

**输出**:

```
NAME        ID            SIZE    PROCESSOR   UNTIL
llama3:70b  bcfb190ca3a7  42 GB   100% GPU    4 minutes from now
```
</Info>

`Processor` 列会显示模型加载到了哪块内存:

- `100% GPU` 表示模型完全加载到 GPU 显存中
- `100% CPU` 表示模型完全加载到系统内存中
- `48%/52% CPU/GPU` 表示模型一部分加载到 GPU、一部分加载到系统内存

## 如何配置 Ollama 服务端?

Ollama 服务端可以通过环境变量进行配置。

### 在 Mac 上设置环境变量

如果 Ollama 以 macOS 应用方式运行,应使用 `launchctl` 设置环境变量:

1. 对每个环境变量,调用一次 `launchctl setenv`。

   ```bash
   launchctl setenv OLLAMA_HOST "0.0.0.0:11434"
   ```

2. 重启 Ollama 应用。

### 在 Linux 上设置环境变量

如果 Ollama 以 systemd 服务方式运行,应使用 `systemctl` 设置环境变量:

1. 调用 `systemctl edit ollama.service` 编辑 systemd 服务,这会打开一个编辑器。

2. 对每个环境变量,在 `[Service]` 小节下添加一行 `Environment`:

   ```ini
   [Service]
   Environment="OLLAMA_HOST=0.0.0.0:11434"
   ```

3. 保存并退出。

4. 重载 `systemd` 并重启 Ollama:

   ```shell
   systemctl daemon-reload
   systemctl restart ollama
   ```

### 在 Windows 上设置环境变量

在 Windows 上,Ollama 会继承你的用户和系统环境变量。

1. 先点击任务栏中的 Ollama 图标将其退出(Quit)。

2. 打开"设置"(Windows 11)或"控制面板"(Windows 10),搜索_环境变量_。

3. 点击_编辑账户的环境变量_。

4. 为你的用户账户编辑或新建 `OLLAMA_HOST`、`OLLAMA_MODELS` 等变量。

5. 点击确定/应用保存。

6. 从 Windows 开始菜单重新启动 Ollama 应用。

## 如何在代理后面使用 Ollama?

Ollama 需要从互联网拉取模型,可能需要通过代理服务器访问模型。使用 `HTTPS_PROXY` 让出站请求走代理。请确保代理证书已安装为系统证书。各平台设置环境变量的方法见上文。

<Note>
  避免设置 `HTTP_PROXY`。Ollama 拉取模型不使用 HTTP,只使用
  HTTPS。设置 `HTTP_PROXY` 可能会中断客户端与服务端的连接。
</Note>

### 如何在 Docker 中让 Ollama 走代理?

启动容器时传入 `-e HTTPS_PROXY=https://proxy.example.com`,即可让 Ollama Docker 容器镜像使用代理。

也可以直接配置 Docker 守护进程走代理。针对 Docker Desktop on [macOS](https://docs.docker.com/desktop/settings/mac/#proxies)、[Windows](https://docs.docker.com/desktop/settings/windows/#proxies)、[Linux](https://docs.docker.com/desktop/settings/linux/#proxies),以及使用 systemd 的 Docker [守护进程](https://docs.docker.com/config/daemon/systemd/#httphttps-proxy)都有相应指引。

使用 HTTPS 时请确保证书已安装为系统证书。如果使用自签名证书,可能需要构建一个新的 Docker 镜像。

```dockerfile
FROM ollama/ollama
COPY my-ca.pem /usr/local/share/ca-certificates/my-ca.crt
RUN update-ca-certificates
```

构建并运行该镜像:

```shell
docker build -t ollama-with-ca .
docker run -d -e HTTPS_PROXY=https://my.proxy.example.com -p 11434:11434 ollama-with-ca
```

## Ollama 会把我的提示词和回答回传给 ollama.com 吗?

Ollama 本地运行。你在本地使用时,我们看不到你的提示词或数据。使用云端托管模型时,我们会处理你的提示词和响应以提供服务,但不会存储或记录这些内容,也绝不用其训练模型。我们只收集提供服务所需的基本账户信息和有限的用量元数据,其中不包含提示词或响应内容。我们不出售你的数据。你可以随时删除自己的账户。

## 如何禁用 Ollama 云端功能?

Ollama 可以通过禁用云端功能,以纯本地模式运行。关闭云端功能后,你将无法使用 Ollama 的云端模型和网页搜索。

在 `~/.ollama/server.json` 中设置 `disable_ollama_cloud`:

```json
{
  "disable_ollama_cloud": true
}
```

也可以设置环境变量:

```shell
OLLAMA_NO_CLOUD=1
```

修改配置后请重启 Ollama。禁用成功后,Ollama 日志会显示 `Ollama cloud disabled: true`。

## 如何把 Ollama 暴露到我的网络中?

Ollama 默认绑定 127.0.0.1 的 11434 端口。可通过 `OLLAMA_HOST` 环境变量修改绑定地址。

各平台设置环境变量的方法请参阅[上文](#如何配置-ollama-服务端)。

## 如何通过 Nginx 反向代理使用 Ollama?

Ollama 运行的是一个 HTTP 服务,可以使用 Nginx 等反向代理服务器对外暴露。配置代理转发请求即可,如不需要把 Ollama 暴露到网络,还可以按需设置必需的请求头。例如 Nginx:

```nginx
server {
    listen 80;
    server_name example.com;  # 替换为你的域名或 IP
    location / {
        proxy_pass http://localhost:11434;
        proxy_set_header Host localhost:11434;
    }
}
```

## 如何使用 ngrok 访问 Ollama?

Ollama 可以通过多种隧道工具访问。例如 Ngrok:

```shell
ngrok http 11434 --host-header="localhost:11434"
```

## 如何配合 Cloudflare Tunnel 使用 Ollama?

配合 Cloudflare Tunnel 使用时,加上 `--url` 和 `--http-host-header` 参数:

```shell
cloudflared tunnel --url http://localhost:11434 --http-host-header="localhost:11434"
```

## 如何允许额外的 Web 来源访问 Ollama?

Ollama 默认允许来自 `127.0.0.1` 和 `0.0.0.0` 的跨域请求。可通过 `OLLAMA_ORIGINS` 配置更多来源。

对于浏览器扩展,需要显式允许该扩展的 origin 模式。若想允许所有浏览器扩展访问,可将 `OLLAMA_ORIGINS` 设为包含 `chrome-extension://*`、`moz-extension://*` 和 `safari-web-extension://*`,或按需指定具体扩展:

```
# 允许所有 Chrome、Firefox 和 Safari 扩展
OLLAMA_ORIGINS=chrome-extension://*,moz-extension://*,safari-web-extension://* ollama serve
```

各平台设置环境变量的方法请参阅[上文](#如何配置-ollama-服务端)。

## 为什么 Windows 10 的 WSL2 里网络很慢?

这会同时影响安装 Ollama 和下载模型。

打开`控制面板 > 网络和 Internet > 查看网络状态和任务`,点击左侧面板的`更改适配器设置`。找到 `vEthernet (WSL)` 适配器,右键选择`属性`。点击`配置`,打开`高级`选项卡。逐个查看属性,找到 `Large Send Offload Version 2 (IPv4)` 和 `Large Send Offload Version 2 (IPv6)`,将这两项都_禁用_。

## 如何预加载模型以获得更快的响应?

使用 API 时,你可以向 Ollama 服务端发送一个空请求来预加载模型。`/api/generate` 和 `/api/chat` 两个端点都支持。

通过 generate 端点预加载 mistral 模型:

```shell
curl http://localhost:11434/api/generate -d '{"model": "mistral"}'
```

通过 chat completions 端点:

```shell
curl http://localhost:11434/api/chat -d '{"model": "mistral"}'
```

使用 CLI 预加载模型:

```shell
ollama run llama3.2 ""
```

## 如何让模型常驻内存,或让它立即卸载?

默认情况下,模型会在内存中保留 5 分钟后卸载。这样在你向 LLM 连续发起大量请求时能获得更快的响应。如果想立即把模型从内存卸载,使用 `ollama stop` 命令:

```shell
ollama stop llama3.2
```

使用 API 时,可以在 `/api/generate` 和 `/api/chat` 端点使用 `keep_alive` 参数,设置模型在内存中的保留时长。`keep_alive` 可设置为:

- 时长字符串(如 "10m" 或 "24h")
- 秒数(如 3600)
- 任意负数,表示模型一直驻留内存(如 -1 或 "-1m")
- '0',表示生成完响应后立即卸载模型

例如,预加载一个模型并让它常驻内存:

```shell
curl http://localhost:11434/api/generate -d '{"model": "llama3.2", "keep_alive": -1}'
```

卸载模型并释放内存:

```shell
curl http://localhost:11434/api/generate -d '{"model": "llama3.2", "keep_alive": 0}'
```

另外,也可以在启动 Ollama 服务端时设置 `OLLAMA_KEEP_ALIVE` 环境变量,统一调整所有模型的内存保留时长。`OLLAMA_KEEP_ALIVE` 支持与上述 `keep_alive` 参数相同的取值类型。环境变量的正确设置方法请参阅[如何配置 Ollama 服务端](#如何配置-ollama-服务端)。

`/api/generate` 和 `/api/chat` 端点上的 `keep_alive` API 参数会覆盖 `OLLAMA_KEEP_ALIVE` 设置。

## 如何管理 Ollama 服务端的最大排队请求数?

如果发送到服务端的请求过多,服务端会返回 503 错误,表示已过载。可以通过设置 `OLLAMA_MAX_QUEUE` 调整可排队的请求数量。

## Ollama 如何处理并发请求?

Ollama 支持两个层级的并发处理。如果你的系统有足够的可用内存(CPU 推理用系统内存,GPU 推理用显存),就可以同时加载多个模型。对单个模型而言,如果加载时有足够的可用内存,它会被配置为允许并行处理请求。

如果可用内存不足以在已加载一个或多个模型的情况下再加载新模型,所有新请求都会排队,直到新模型可以加载。当先前的模型空闲时,会有一个或多个模型被卸载,为新模型腾出空间。排队的请求会按顺序处理。使用 GPU 推理时,新模型必须能完整放入显存,才允许并发加载多个模型。

对单个模型开启并行请求处理,会把上下文大小乘以并行请求数。例如,2K 上下文配 4 个并行请求,会得到 8K 的上下文和额外的内存分配。

大多数平台上,可用以下服务端设置调整 Ollama 处理并发请求的方式:

- `OLLAMA_MAX_LOADED_MODELS` - 在可用内存放得下的前提下,可并发加载的最大模型数。默认为 3 \* GPU 数量,CPU 推理时默认为 3。
- `OLLAMA_NUM_PARALLEL` - 每个模型同时处理的最大并行请求数,默认 1。所需内存会按 `OLLAMA_NUM_PARALLEL` * `OLLAMA_CONTEXT_LENGTH` 扩展。
- `OLLAMA_MAX_QUEUE` - Ollama 繁忙时在拒绝新请求前允许排队的最大请求数。默认为 512。

注意:由于 ROCm v5.7 在显存上报方面的限制,Radeon GPU 的 Windows 目前最多默认 1 个模型。待 ROCm v6.2 发布后,Windows Radeon 将遵循上述默认值。你可以在 Windows 的 Radeon 上启用并发模型加载,但请确保加载的模型数量不超过 GPU 显存容量。

## Ollama 如何在多 GPU 上加载模型?

加载新模型时,Ollama 会把模型所需的显存与当前可用显存做比较。如果模型能完整放进任意单个 GPU,Ollama 就会把模型加载到该 GPU。这通常能带来最佳性能,因为它减少了推理期间跨 PCI 总线传输的数据量。如果模型无法完整放进单个 GPU,则会分摊到所有可用 GPU 上。

## 如何启用 Flash Attention?

Flash Attention 是大多数现代模型支持的特性,能随上下文规模增长显著降低内存占用。当所选后端和设备支持时,Ollama 会自动使用 Flash Attention。若要强制开启,启动 Ollama 服务端时设置 `OLLAMA_FLASH_ATTENTION=1`;要关闭则设 `OLLAMA_FLASH_ATTENTION=0`。

## 如何设置 K/V cache 的量化类型?

在启用 Flash Attention 的前提下,对 K/V 上下文缓存做量化可以显著降低内存占用。

要在 Ollama 中使用量化 K/V cache,可设置以下环境变量:

- `OLLAMA_KV_CACHE_TYPE` - K/V cache 的量化类型。默认为 `f16`。

<Note>
  目前这是一个全局选项——即所有模型都会以指定的量化类型运行。
</Note>

当前可用的 K/V cache 量化类型:

- `f16` - 高精度、高内存占用(默认)。
- `q8_0` - 8 位量化,内存占用约为 `f16` 的 1/2,精度损失极小,通常对模型质量没有可感知的影响(不用 f16 时推荐)。
- `q4_0` - 4 位量化,内存占用约为 `f16` 的 1/4,精度损失中小程度,在较大上下文下可能更明显。

缓存量化对模型回答质量的影响程度取决于模型和任务。GQA 数量高的模型(如 Qwen2)受量化影响的精度损失可能比 GQA 数量低的模型更大。

你可能需要尝试不同的量化类型,在内存占用与质量之间找到最佳平衡。

## 在哪里可以找到我的 Ollama 公钥?

**Ollama 公钥**是密钥对的公开部分,它让你的本地 Ollama 实例能与 [ollama.com](https://ollama.com) 通信。

以下场景需要用到它:
* 向 Ollama 推送模型
* 从 Ollama 拉取私有模型到本机
* 运行 [Ollama Cloud](https://ollama.com/cloud) 上托管的模型

### 如何添加密钥

* 在 **Mac** 和 **Windows 应用**中通过 Settings 页面登录

* **通过 CLI 登录**

```shell
ollama signin
```

* 在 **Ollama Keys** 页面**手动复制粘贴**密钥:
[https://ollama.com/settings/keys](https://ollama.com/settings/keys)

### Ollama 公钥的位置

| 操作系统 | `id_ed25519.pub` 路径 |
| :- | :- |
| macOS 	| `~/.ollama/id_ed25519.pub`			|
| Linux		| `/usr/share/ollama/.ollama/id_ed25519.pub`	|
| Windows	| `C:\Users\<username>\.ollama\id_ed25519.pub`	|

<Note>
  请把 &lt;username&gt; 替换为你实际的 Windows 用户名。
</Note>

## 如何禁止 Ollama 随登录自动启动?

Windows 和 macOS 版 Ollama 在安装时会注册为登录启动项。如果你不希望 Ollama 自动启动,可以禁用它。除非卸载应用,否则 Ollama 在升级后会保留这一设置。

**Windows**
- 在`任务管理器`中进入`启动应用`选项卡,搜索 `ollama`,点击`禁用`

**MacOS**
- 打开`设置`并搜索"登录项"(Login Items),在`允许在后台`下找到 `Ollama` 条目,点击开关将其禁用。
